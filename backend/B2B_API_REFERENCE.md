## 🏛️ Integration Context
This document serves as the technical master record for the **Flow-Q Headless Implementation**. All routes below are designed to be consumed by third-party partner applications (e.g., custom patient apps, local kiosk hardware, or ERP systems).

### **Header Requirements**
Every request must include the following headers:
```http
Content-Type: application/json
x-api-key: {YOUR_PARTNER_API_KEY}
```

## 🔍 I. Service Discovery
Endpoints used to discover the clinical landscape and inventory availability.

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| **GET** | `/services` | Lists all active clinical services with live wait-time estimates and agent counts. |
| **GET** | `/services/:id/slots` | Retrieves available 15-min appointment windows for a specific date (YYYY-MM-DD). |

---

## ⚡ II. Live Queue Orchestration
The core actuators for managing real-time patient flow and state mutations.

| Method | Endpoint | Action / Description |
| :--- | :--- | :--- |
| **GET** | `/queue` | Fetches the live organization-wide board. Supports filering by `serviceId` or `status`. |
| **POST** | `/queue/check-in` | **Direct Ingress:** Adds a walk-in patient directly to the waiting list. |
| **GET** | `/queue/:uniqueLinkId` | Retrieves a specific identity's position, metrics, and state. |
| **PATCH** | `/queue/:uniqueLinkId/action` | **Primary Actuator:** Mutates state. Payloads: `{"action": "call" | "complete" | "cancel"}`. |
| **PUT** | `/queue/:uniqueLinkId/priority` | Bypasses standard sorting to move a patient to the #1 position. |
| **PUT** | `/queue/:uniqueLinkId/notes` | Attaches discrete clinical or operational notes to an active board entry. |

## 📅 III. Appointment Lifecycle
Management of scheduled reservations before they enter the live clinical mesh.

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| **GET** | `/appointments` | List all upcoming reservations for the day or specific service. |
| **POST** | `/appointments/book` | **Reservation Ingress:** Creates a future-dated appointment. |
| **PATCH** | `/appointments/:id/arrive` | **The Handshake:** Converts a scheduled appointment into a live `waiting` queue entry. |
| **PUT** | `/appointments/:id/cancel` | Terminates a reservation before it activates. |

## 🛡️ Security & Zero-PII
The v2 engine is designed for **Privacy-by-Design**.
*   All public-facing tracking utilizes `uniqueLinkId` (UUID) instead of database primary keys.
*   The `x-api-key` is securely hashed and authenticated against the **Organization Model**.
*   PII Data (Name/Phone) can be masked in the `piiFilter` middleware depending on the Organization's `piiMode` setting.
